## 1. الهدف والجمهور
- نموذج تفاعلي لوحدة **إدارة الصيانة** يعمل كنظام حقيقي (بيانات واقعية مترابطة، حالات تحميل وفراغ وخطأ، تصفية، نماذج وتحقق، دورات حالة، سجل تدقيق) لعرضه على الإدارة والتحقق من التجربة قبل البناء الفعلي.
- يُضاف كوحدة ثالثة داخل `mock_enjaz_erp` بجانب الموجودات الثابتة وإدارة العقود.
- خارج النطاق: خلفية حقيقية، مصادقة فعلية، ربط فعلي مع المخزون والمبيعات والمالية وHR وElsa ووحدة الجدولة؛ كلها نتائج محاكاة داخل الوحدة.

## 2. القرارات المؤكدة (من الاكتشاف)
| البند | القرار |
|---|---|
| التقنية | تقنية المشروع الحالي: Vite + React 18 + TypeScript + Tailwind v3، HashRouter، `lucide-react`، مخزن عميل في `localStorage` (مفتاح خاص بالوحدة، `DATA_VERSION`). لا تبعيات جديدة. (انحراف مسجل عن Next.js الافتراضي في الدليل، كما في الوحدتين الأخريين.) |
| الموقع | `src/modules/maintenance`، المسار `/maintenance`، `router.tsx` خاص بالوحدة، `MaintenanceApp.tsx`، مجموعة ثالثة في `src/shell/Sidebar.tsx` وبطاقة في `Hub.tsx`. التوثيق في `docs/maintenance/`. |
| العزل | الوحدة **معزولة**: بذرتها الخاصة (أصول، عملاء، مواد، فنيون، مخازن) ونتائج تكامل محاكاة. الربط بأصل ثابت أو عقد يظهر رقمًا مرجعيًا فقط. لا استيراد من وحدتي الأصول والعقود. |
| العمق | **عمق النسخة الأولى كاملًا**: الدورة كاملة + بطاقة الأصل + الجدولة + التقارير. الصيانة الوقائية وتغطية العقود ولوحة السحب والمهارات تظهر "قريباً". |
| الأدوار | صلاحيات حقيقية تغيّر الأزرار والقوائم + شاشة مصفوفة صلاحيات. الأدوار: موظف استقبال، فني، مدير ورشة، منسق جدولة، أمين مخزن، محاسب، مدير مالي، مسؤول نظام. |
| الجدولة | لوحة أسبوعية (صفوف الفنيين والرافعات × أيام الأسبوع)، الحجز بنقرة على خانة فارغة عبر نافذة، النقر على الحجز لنقله أو إلغائه أو بدئه أو إكماله. بلا سحب وإفلات. |
| البيانات | حجم متوسط: ~30 أصلًا (سيارات، مكيفات، مولدات، رافعة الشركة، أصول داخلية)، ~45 أمر عمل بكل الحالات، 10 فنيين، ورشة واحدة + صيانة ميدانية، تاريخ 3 أشهر للتقارير. يوم العرض الثابت **2026-11-07** من `data/asof.ts`. |
| المنطقة والعملة | عراقي: أسماء ومناطق بغداد، الدينار IQD، أرقام وتواريخ عربية الواجهة. |
| الطباعة | معاينة طباعة A4 عربية لـ: إيصال الاستلام، عرض سعر الإصلاح (التقدير) مع خانة موافقة العميل، بطاقة أمر العمل للفني، خط السير اليومي. |
| صفحة الصيانة في الأصول | **لا تُمس**. الحدود المعتمدة: الأصول للجانب المحاسبي، والصيانة للتشغيل (§37.5.1 في فرع `feat/add_assets_management`). |
| الحفظ | **بلا commit**: أبني وأتحقق وأترك التغييرات للمراجعة. |

## 3. النطاق الوظيفي (من الخطة المعتمدة)
1. **البيانات الرئيسية**: أنواع الصيانة، فئات الأصول وقوالب سماتها، أكواد الأعطال، العمليات القياسية، الورشة والرافعات، أنواع مصاريف الصيانة وحساباتها، الفنيون (معدل تكلفة قياسي)، إعدادات الوحدة (الصرف التلقائي، منع الصرف فوق المتاح، الشريك الداخلي، حدود الاعتماد ومستوياته، مدة إعادة العمل، وضع الاعتماد).
2. **بطاقة الأصل**: الهوية والمالك والضمان والموقع والأصل الأب والحالة والسمات، امتداد السيارة، العدادات وسجل قراءاتها، تاريخ الأصل.
3. **طلب الصيانة**: الاستلام وإيصاله وقراءة العداد.
4. **التقدير**: أسطر قطع وعمالة وخدمات وتغطية لكل سطر، النسخ والمراجعة، الاعتماد الداخلي بقواعده الثماني (حدود، مستويات، منع اعتماد الذات، سحب، انتهاء صلاحية، اعتماد تلقائي تحت الحد)، موافقة العميل المنفصلة.
5. **أمر العمل**: الحالات (Created → Planned → Scheduled → InProgress → WaitingParts/WaitingCustomer/OnHold → QualityCheck → Completed → Closed، إلغاء، إعادة فتح)، العمليات، القطع (مخطط/مستهلك/مصروف)، الساعات، الحجز عند البدء، الصرف التلقائي عند الإكمال مع منع ما فوق المتاح، كود العطل إلزامي، القطع المُزالة ومصيرها، إعادة العمل خلال 30 يومًا.
6. **الفوترة والعربون**: فاتورة خدمة مرحَّلة ومقفلة (محاكاة)، حساب الإيراد من البطاقة، إعادة فتح الفوترة بعد الإلغاء، منع الإلغاء مع دفعة، عربون على الحساب وتخصيصه، حالة السداد.
7. **المحاسبة المحاكاة**: قيود سند الصرف حسب نوع المصروف، قيد الفاتورة، قيد العربون — للعرض فقط.
8. **الجدولة**: الحجز من أمر العمل ومن اللوحة، عمل ورشة وصيانة ميدانية، تعارض الفني والرافعة، الإجازات (من HR محاكاة)، ربط الحالات، قائمة "بانتظار الجدولة".
9. **ساعات العمل**: تسجيل الفني، تأكيد المشرف، تقرير الفرق مع الحضور (حضور محاكى).
10. **التقارير**: مجموعات §28 (التشغيل، الأداء، الجودة، المالية، الأصول والعملاء، المخزون، الاعتماد) + تقارير الجدولة §38.6، ولوحة مؤشرات الوحدة.
11. **سجل التدقيق والصلاحيات**.

## 4. افتراضات اتخذتها (قابلة للتعديل)
- واجهة "صفحة الوحدة" (Hub) بطاقات للشاشات، كما في الوحدتين الأخريين.
- الاعتماد عبر Elsa يُحاكى بصندوق مهام لكل معتمِد داخل الوحدة.
- حدود الاعتماد الافتراضية: حتى 1,000,000 تلقائي؛ حتى 5,000,000 مدير الورشة؛ فوقها مدير الورشة ثم المدير المالي.
- معدل تكلفة العمالة القياسي حسب الوظيفة: 12,500 د.ع/ساعة للفني، 18,000 للفني الأول.
- أرقام المستندات بصيغة الخطة: `MRQ-2026-000001` و`MES-…` و`MWO-…`، وأرقام محاكاة للمستندات الخارجية: `GI-…` (صرف) و`INV-…` (فاتورة) و`RC-…` (قبض) و`SCH-…` (حجز).
